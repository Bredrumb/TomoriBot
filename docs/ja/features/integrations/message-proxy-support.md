メッセージプロキシ対応は、外部のDiscord Botが元のメッセージを削除し、Webhook経由で再投稿する仕組みにTomoriBotを対応させる機能です。選択したサービスが元のメッセージと送信者を正確に検証できた場合だけ、返信の判定を再投稿へ引き継ぎます。

## サービスを選ぶ

現在対応しているサービスを有効にするには、`/personal message-proxy service:pluralkit`を実行します。無効にするには`/personal message-proxy service:none`を実行します。この設定は元のメッセージを送るDiscordアカウントの個人設定で、サーバーをまたいで適用されます。

現在選べるのは**PluralKitのみ**です。メンバーごとのアイデンティティ、記憶、制限については[PluralKitサポート](/ja/features/integrations/pluralkit-support/)をご覧ください。

## 安全性のための検証

TomoriはWebhookの名前、アバター、投稿時刻、削除メッセージとの近さだけで送信者を推測しません。選択したサービスが、Webhookメッセージを元のメッセージとDiscordアカウントへ正式に対応付ける必要があります。検証できない、失敗する、または複数サービスの主張が競合する場合、Webhookは無視され、アイデンティティや記憶も作成されません。

そのため、Tupperboxは現在選択肢にありません。公開ドキュメントにはプロキシ機能の説明がありますが、TomoriBotが安全に利用できる公開のメッセージ証明APIは記載されていません。

## 短い待ち時間

サービスを選択すると、Tomoriはアカウントから送られた通常のサーバーメッセージを処理する前に少し待ちます。この間にサービスが削除と再投稿を行えます。プロキシされなかったメッセージは待機後に続行し、検証された再投稿は元のトリガー判定と返信先を引き継ぎます。

セルフホスト環境では`MESSAGE_PROXY_WAIT_MS`で待機時間を調整できます。PluralKit APIのタイムアウトや任意トークンなど、サービス固有の通信設定は別に管理されます。
