NovelAIは、テキストモデル（`GLM 4.6`、`Xialong`、`Kayra`、`Erato`）とアニメ画像生成を接続します。両方にNovelAIを使用することも、その画像生成を別のチャットプロバイダーと組み合わせることもできます。

## テキストモデルとサブスクリプション
<!-- anchor: text-models-and-subscription -->

`GLM 4.6` がデフォルトのテキストモデルです。`Xialong` と `Erato` には有効なOpusサブスクリプションが必要です。`Xialong` を選択すると、保存されたサーバーキーまたは個人キーが確認されます。キーを追加する前に選択した場合は、キーを追加した時点で確認が実行されます。提供キーのサブスクリプションによってコンテキスト許容量が決まります。サーバー管理者は `/novelai usage` でOpusの生成許容量を確認できます。

NovelAIの [チャットフォーマットガイド](https://docs.novelai.net/en/text/chatformat/) には、`Kayra` と `Erato` で使用されるストーリースタイルのアプローチが説明されています。`GLM 4.6` と `Xialong` は個別のチャットテンプレートを使用します。以下のフィルタリングと推敲は、TomoriBot独自のアダプテーションです。

## サンプリングプリセット
<!-- anchor: sampling-presets -->

テキストモデルを切り替えると、選択されたモデルに応じて `Carefree-Kayra`、`Erato-Shosetsu`、または `Default-Xialong` が読み込まれます。`GLM 4.6` は独自のデフォルトを使用します。切り替えにより温度、top-k、top-p、min-pがリセットされ、サーバーと個人の両方のモデル切り替えでそれらのサンプラーが有効化されます。プリセットやサンプラーは `/config` > `モデル` > `テキストサンプラーとパラメーター` で変更できます。その後の編集も有効のまま維持され、同じモデルでキーを差し替えてもサンプラー設定は維持されます。

## コンテキストと設定
<!-- anchor: context-and-settings -->

除外された設定は、他のプロバイダー用に `/config` > `動作` > `一般的な動作` で保存されたまま維持されます。

| コンテンツまたは設定 | NovelAIでの取り扱い |
|---|---|
| ペルソナの属性、サンプル対話、会話、記憶 | 表示可能な個人の記憶や短期記憶を含めて保持されます。プライバシーと記憶タグのフィルターも引き続き適用されます。 |
| システム、ペルソナ、チャンネルの各プロンプト、コンテキストノート、ヒューマナイザー規則、条件付け、SillyTavernの指示 | 除外されます。XialongはNovelAIのシステムプロンプトを使用し、GLM、Kayra、Eratoにはシステムブロックがありません。 |
| ステータス、時間/チャンネル/サーバー情報、ドキュメント、絵文字/スタンプ/スプライト一覧 | 除外されます。 |
| 記憶ツールの促し | 個人設定による上書きやフォールバックの前に構築された促しを含め、除外されます。 |
| ATTGメタデータと品質スター | ATTGは作者（Author）、タイトル（Title）、タグ（Tags）、ジャンル（Genre）を意味します。Xialongは永続情報の先頭にメタデータを配置し、デフォルトで4スターを使用します。Eratoは設定されたスターを使用し、Kayraはスターを除外します。 |
| 返答プリフィル | プリフィル設定で許可されている場合に保持されます。 |
| ツールとメディア | テキストモデルによるツール呼び出しや画像/動画入力はありません。スラッシュコマンドおよび個別の画像生成コマンドは引き続き利用可能です。 |
| トークン制限 | 返信用に空きを確保しつつローカルでカウントされます。設定された返答長はプリセット長よりも優先され、収まるように縮小される場合があります。 |

既知の外部話者ラベルおよび単独の `---` または `***` の行は、共通の話者停止設定がオフの場合でも出力を停止します。応答するペルソナの名前、別名、スプライトラベルは引き続き許可されます。ローカルガードはコードを保護しますが、リテラルなAPI停止文字列は生成されたコード内でも一致する可能性があります。

## コンテキストのトリミング
<!-- anchor: context-trimming -->

記憶はコンテキストウィンドウの最大20%を使用し、古いエントリから順に削除されます。それでもプロンプトが収まらない場合、TomoriBotは以下の順序でトリミングします：

| 順序 | 削除されるコンテンツ | 保護されるコンテンツ |
|---|---|---|
| 1 | 余分なサンプル対話 | 利用可能な1つのサンプル対話 |
| 2 | 記憶（古いエントリから順） | 最小値なし |
| 3 | 古い会話履歴 | 最大2つの直近の会話 |

ペルソナの属性、ATTGメタデータ、現在のターンも保護されたまま維持されます。保護されたコンテキストが収まらない場合、生成は失敗します。トリミングを行っても、保存された記憶やメッセージは変更されません。

`/tool prompt snapshot` で、最終的なプロンプト、トークン数、返答上限、トリミングレポートを確認できます。

## テキストの推敲とDiscordへの送信
<!-- anchor: text-polishing-and-discord-delivery -->

推敲は、トークンカウントの前に、4つのNovelAIモデルすべてに送信される履歴、記憶、サンプル対話のコピーのみを変更します。保存されたテキストや他のプロバイダーは変更されず、文法が書き直されることもありません。

- **テキストの大文字表記が適切に修正されます**：ラテン文字の文頭や行頭が大文字化され、既知のペルソナ名は設定された大文字小文字が使用されます。
- **散文の行に句読点が付与されます**：不足している末尾のピリオドが追加され、既存の句読点、改行、空行はそのまま維持されます。
- **フォーマットされた散文が推敲されます**：`*kisses juno*` は `*Kisses Juno.*` に変換されます。太字、下線、取り消し線、スポイラーも同じ規則に従います。インライン強調は大文字小文字を維持します（名前を除く）。
- **コードとマークアップが保持されます**：コード、URL、メンション、Discordマークアップ、リスト、見出し、引用、表、区切り線は、内容や構造が維持されます。
- **散文以外の行頭と行末が尊重されます**：コードフェンス、URL、メンション、絵文字、非ラテン文字で始まる行は文のフォーマットをスキップします。絵文字、顔文字、コード、リンクの末尾に余計なピリオドが付くことはありません。
- **長期記憶はプレーンな内容を使用します**：追加された所有者ラベル、データベースID、タグプレフィックスは除外され、解決された名前は残ります。
- **生成された履歴アノテーションが削除されます**：返信の参照、リアクションのメタデータ、管理通知は除外されます。ジェスチャーはアクションになり、シーンと要約はシステムラッパーが外されます。`System:` を含むユーザーの文字通りのテキストは保持されます。
- **プリフィルはそのまま維持されます**：明示的な返答プリフィルと継続フラグメントは変更されません。
- **Discordへの送信は設定に従います**：大文字小文字、句読点、メッセージの分割は引き続きヒューマナイザーが制御します。後の履歴は再度推敲されます。失われた句読点を完全に復元することはできません。

## 画像生成
<!-- anchor: image-generation -->

`/config` > `モデル` > `モデルの切り替え` で、`NovelAI画像` スロットにモデルを割り当てます。メンバーは `/novelai generate image` で直接画像を生成するか、アクティブなテキストプロバイダーがツール呼び出しをサポートしている場合はチャットで依頼できます。

`Default + Image Generation Expert` プリセットは、NovelAI向けに画像掲示板スタイルのタグを使用し、相互作用やテキスト配置に必要な場合は短い説明を追加します。複数のキャラクターが登場するシーンでは、TomoriBotは共通の背景やカメラの指示を、各キャラクターの外見や動作から分離して維持します。

読みやすいセリフを生成するには、正確な対話を含めるようTomoriBotに依頼してください。NovelAI画像ツールは、キャラクターの対話を末尾の `Text:` セクションに自動的に配置します。V4とV4.5は英語のテキストをサポートし、V5は日本語と中国語もサポートします。看板や画面のテキストは、共通のシーンプロンプト内で説明できます。要求するテキストは短く保ち、ポジティブタグに `no text` を含めないようにしてください。配置やタイポグラフィ（日本語の縦書きを含む）は保証ではなく提案として扱われます。
