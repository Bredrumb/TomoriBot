TomoriBotは永続的なメモリーシステムを備えているため、会話をまたいで事実を記憶できます。このページでは*彼女が何を知っているか*（事実、コンテキスト、ドキュメント）について説明します。*どのように振る舞うか*（性格、トーン）については、[マルチペルソナ](/ja/features/chatting-personality/multiple-personas/)を参照してください。

## 個人とサーバーの記憶

長期記憶には2つの種類があります：

- **個人の記憶**（`/memory personal add`） — 個々のユーザーに関する事実。例：「Amaoriは猫が好き」「ダークモードを好む」「ピーナッツアレルギー」。これらは*あなた*に紐付いており、**すべてのサーバーで追従**します。ただし、あなたがアクティブに参加している会話でのみ引き出されます。
- **サーバーの記憶**（`/memory server add`） — サーバー全体に関連する情報。例：「ゲームナイトは毎週金曜日の午後8時」「NSFWの投稿禁止」「#generalはアナウンス用」。これらはサーバー内に留まり、常に考慮されます。

削除するには `/memory personal remove` または `/memory server remove` を使用します。メモリーは削除されるまで保持されます。

:::tip
最良の結果を得るために、メモリーは簡潔かつ明確に保ってください。`/memory personal export`、`/memory server export`、または `/status` でいつでも確認できます。
:::

## タグ付け：メモリーの有効化を制御

デフォルトでは、**すべてのプロンプトに対してすべてのメモリーが送信されます**。タグ付けを使用すると、どのメモリーをどこで有効にするかを制御できます。`/memory tagging set` で有効化できます。

### キーワードタグ

- キーワードタグの**ない**メモリーは常に有効です（デフォルト）。
- キーワードタグの**ある**メモリーは、可視コンテキスト内にキーワードが現れたときにのみ有効になります。
- `/tool prompt snapshot` を使用して、現在どのメモリーが有効になっているかを確認できます。

### チャンネルタグ

- `#channel` タグを持つメモリーは、そのチャンネル内でのみ有効になります。
- チャンネルタグはキーワードタグと組み合わせることができます。
- ドキュメント知識ベース（RAG）を使用している場合、チャンネルタグはドキュメントや抽出された履歴にも適用されます。

Discordで `/help memory-tagging` を実行すると、同じ概要を確認できます。

## ドキュメント知識ベース（RAG）

サーバー管理者は参照用のドキュメントを提供できます：

- `/memory document add` — テキスト、PDF、またはMarkdownファイルをサーバーの知識としてアップロードします。
- `/memory history import` — チャンネルの履歴を検索可能な知識として抽出します。
- ドキュメントはチャンク化され、検索可能な埋め込み（エンベディング）として保存されます。回答時に関連するコンテンツが自動的に取得されます。
- チャットで直接共有されたファイル添付（PDF、ソースコード、Markdown、JSON、YAMLなど）を読むこともできます。読んでほしいと頼むだけです。
- `/memory document view` — 保存されたドキュメントをチャンクごとに閲覧します。サーバー管理者はドキュメント全体を削除することなく、個々のチャンクの編集、ドキュメントのチャンネルタグの更新、単一チャンクの削除を行えます。
- 保存されたドキュメントは `/memory document remove` で削除できます。`/memory history remove` は `/memory history import` で作成されたドキュメントのみを一覧表示するフィルター付きショートカットです。

`/memory document view` は、ペルソナスコープとサーバーワイドスコープのどちらでも、セッション全体を単一のComponents V2メッセージ内で処理します。ペルソナ選択、ドキュメント選択、読み込み、チャンク移動、編集/削除の確認、進行状況、成功・エラー表示、タイムアウトのすべてが同一のメッセージ内で入れ替わります。最大25件のドキュメント一覧は直接開かれ、それ以上の場合は2つ目のページ選択メッセージではなく、その場で範囲選択ボタンが表示されます。タイムアウト時も、現在のチャンクはコントロールが無効化された状態で読み取り可能なまま残ります。**Close** を押すとプライベートワークフローメッセージが削除されます。

ドキュメントの選択はメタデータやチャンクが読み込まれる前に応答処理（acknowledge）されます。編集の送信も埋め込み生成や保存処理の前に応答処理されます。コンテンツやチャンネルタグの変更は書き込み成功後にのみ反映され、キャッシュの無効化はそれらの書き込み後に行われます。最後のチャンクを削除すると空になったドキュメント自体も削除され、メッセージは最終結果表示へと変化します。

### 履歴インポートのプロンプト

チャンネル履歴をインポートする際、`prompt` オプションによって TomoriBot の記憶抽出方法が変化します：

- **Conversation** — 通常のチャットから独立した事実を抽出します。代名詞を解決し、日付や時間が明示的または推測可能な場合は絶対タイムスタンプを使用します。
- **Roleplay** — 細かな動きをすべて残そうとするのではなく、シーン、ロア（伝承・設定）、人間関係、印象的な出来事を検索します。
- **In-Character** — 選択されたペルソナの視点から記憶を抽出します。そのペルソナのプロンプト、属性、既存の記憶、関連ドキュメントをコンテキストとして使用します。

インポート前にプロンプトが表示されるため、チャンネルやシーンに合わせて調整できます。

履歴インポートはドキュメントとして保存されるため、`/memory document view` や `/memory document remove` も同様に利用できます。

**埋め込みモデルが必要です**。`/model embedding` で設定します。[プロバイダーとモデル](/ja/features/setup-administration/providers-and-models/)を参照してください。

ファクト抽出には構造化JSON出力に対応したテキストモデルが必要です。モデルが構造化出力を生成できなかった場合、インポートは中断され、「ファクトが見つかりませんでした」ではなくプロバイダーのエラー内容がそのまま表示されます。多くの場合、JSONスキーマ出力に対応したモデルに切り替えることで解決します。実際に保存すべき内容がなかったバッチについては、従来どおり「ファクトが抽出されませんでした」と表示されます。

## 短期記憶（STM）

TomoriBot は発言中の現在のチャンネルのメッセージを容易に読み取ることができますが、STM を使用すると長期記憶として保存することなく以下のことが可能になります：
1. コンテキスト内でチャンネルの現在のシナリオ/状況を一時的に強化する
2. 他のチャンネルやサーバーでの会話を一時的に記憶する

**彼女は自分が参加した会話のみを記憶します。** 彼女が返信したときにのみチャンネルの記憶を更新するため、誰も彼女に話しかけない賑やかなチャンネルには何も残りません。

各チャンネルの STM はデフォルトで24時間後に期限切れとなり、`/personal privacy` でオプトアウトしている場合、あなたのメッセージは一切含まれません。

### 彼女に見えるもの・見えないもの

| 場所 | 意味 |
|---|---|
| **サーバー内** | 1人ごとではなく、チャンネルごとに1つの共有記憶。個人ごとにメモを取っているわけではありません。 |
| **DM内** | あなただけのもの。 |
| **他のチャンネル** | 同じサーバー内の他のいくつかのチャンネルでの最近の会話を呼び出すことができます。 |
| **プライベートチャンネル** | `/server private-channels` で設定された内容はそこに留まり、他へ露出することはありません。 |
| **他のサーバー** | `/personal stm` → `crossserver` をオンにしない限り露出することはありません。オンにした場合でも*あなた自身の*会話のみが追従します。 |
| **各ペルソナ** | それぞれ独立した記憶を保持しているため、ペルソナを切り替えると記憶も切り替わります。 |

各チャンネルの記憶には、直近の数通のメッセージと、会話の進行に合わせて彼女自身が書き更新する短い要約が保持されます。静かな時間が数時間続くと自動的に消えていきます。

### コマンド

| コマンド | 役割 |
|---|---|
| `/persona stm view` | このチャンネルに対して彼女が保持している要約を確認する |
| `/persona stm edit` | 要約を修正するか、自分で記述する |
| `/personal stm` | サーバー間での呼び出しをオプトインするか、自身の記憶を消去する |
| `/tool refresh` | 今すぐこのチャンネルの記憶を忘れさせる |
| `/server stm parameters` | 更新頻度や保持する詳細度を設定する |
| `/server stm categories-edit` | 要約を最大5つのラベル付きフィールド（*現在のシーン*、*雰囲気*など）に差し替える |
| `/server stm prompt-edit` | 記憶保持の指示プロンプトを書き換える |
| `/server stm manage` | 保存されている記憶を確認またはクリアする |
| `/server stm privacy-bypass` | プライベートチャンネルの記憶を他へ露出できるようにする |
| `/capabilities manage` | 機能をオン/オフにする（保存された記憶はどちらの場合も保持されます） |

誰でも `/persona stm view` と `/personal stm` を実行できます。それ以外は サーバーの管理 権限が必要です。

:::tip
これらの STM コマンドは上級ユーザー向けです。`/personal stm` でサーバーをまたいで記憶させたい場合を除き、デフォルト設定のまま使用することをお勧めします。
:::

## 条件付け

`/conditioning` はペルソナごと・サーバーごとの記憶であり、時間の経過とともにペルソナの振る舞いを誘導します。完全な属性やシステムプロンプトよりも軽量な後押しとなります。特定のキャラクターが特定のサーバーでどのように振る舞うべきかを強化するために使用します。

---

**プライバシー：** 彼女が何を保存し、それをどのようにエクスポートまたは削除するかについては、[データの取り扱い](/ja/features/knowledge/data-handling/) および `/legal privacy` を参照してください。`/personal privacy` でメモリー機能を完全にオプトアウトすることもできます。
