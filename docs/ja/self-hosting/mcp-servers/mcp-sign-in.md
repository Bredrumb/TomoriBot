一部のMCPサーバーでは、トークンを貼り付ける代わりに管理者がアカウントへサインインする必要があります。セルフホストボットがこのサインインを提供するのは、`TOMORI_PUBLIC_BASE_URL` が設定されている場合のみです。設定されていない場合は、`認証トークン` でトークンを受け取るMCPサーバーのみが動作します。

[公開デプロイ済みボット](https://discord.com/oauth2/authorize?client_id=841644102059556915)を使用している場合、このページの手順は不要です。[MCPサーバー](/features/capabilities/tools-and-extensions/mcp-servers/)を参照してください。

## ベースURLを選択する

`.env` の `TOMORI_PUBLIC_BASE_URL` にパスのないアドレスを設定し、ボットを再起動してください：

| 値 | 使用する条件 |
|---|---|
| `http://127.0.0.1:8080` または `http://localhost:8080` | ボット自身のマシン上のブラウザーでサインインを完了する場合。ドメインやトンネルは不要です。 |
| `https://<your-host>` | 管理者が各自のコンピューターからサインインする場合。ボットへ転送する公開HTTPSアドレスが必要です。 |

この変数を設定すると、ボットのHTTPサーバーが `PORT`（デフォルト `8080`）で起動し、すべてのネットワークインターフェースでリッスンします。進行中のサインイン状態はメモリ上に保持されるため、途中でボットを再起動した場合はDiscordからやり直す必要があります。

## ループバックアドレス

- `PORT` と同じポートを使用してください。両者が異なる場合、ボットは起動時に警告をログに出力します。
- ボットのマシン上のブラウザーでサインインを完了してください。別のコンピューターから行う場合は、まずSSHでポートフォワーディングを行ってから、そのコンピューターのブラウザーで `サインイン` を選択します：

  ```sh
  ssh -L 8080:127.0.0.1:8080 "<user>@<bot-host>"
  ```

- ループバックアドレスを受け入れるかどうかは各サービス側の判断によります。拒否された場合は、代わりにHTTPSアドレスまたはトークンを使用してください。

## HTTPSアドレス

公開アドレスからボットの `PORT` へ、以下のパスを転送してください：

- `GET /oauth/callback`
- `GET /oauth/mcp/start`
- `POST /oauth/mcp/confirm`
- `GET /oauth/client.json`

サービスは `https://<your-host>/oauth/client.json` によってボットを識別するため、最初のサインイン前にホスト名を決定し、それを維持してください。

## Docker Compose

Composeではボットのポートは公開されません。`docker-compose.yaml` の隣に `docker-compose.override.yaml` を作成してください：

```yaml
services:
  tomoribot:
    ports:
      - "127.0.0.1:8080:8080"
```

`127.0.0.1:` プレフィックスは必ず維持してください。これがないと、ネットワーク上のすべてのコンピューターがボットのHTTPサーバーにアクセスできてしまいます。同じマシン上で動作するリバースプロキシやトンネルからは、このポートへ転送できます。
