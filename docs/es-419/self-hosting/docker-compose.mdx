Docker Compose ejecuta TomoriBot y PostgreSQL juntos en contenedores. Es la tercera opción de instalación junto con el [asistente de configuración](/self-hosting/setup-wizard/) y la [instalación manual](/self-hosting/manual-setup/): elígela cuando quieras ejecutar todo en Docker sin instalar Bun ni PostgreSQL en tu sistema host. Omite el asistente de configuración interactivo y configura la conexión a la base de datos automáticamente.

## 1. Obtén el código

```sh
git clone https://github.com/Bredrumb/TomoriBot.git
cd TomoriBot
```

## 2. Valores requeridos de `.env`

Comienza desde el archivo de ejemplo:

<Tabs syncKey="operating-system">
<TabItem label="Windows">

```powershell
Copy-Item .env.example .env
```

</TabItem>
<TabItem label="Linux">

```bash
cp .env.example .env
```

</TabItem>
<TabItem label="Mac">

```bash
cp .env.example .env
```

</TabItem>
</Tabs>

Establece estas variables requeridas en `.env`:

| Variable | Valor |
|---|---|
| `DISCORD_TOKEN` | Tu token de bot de Discord (habilita los intents privilegiados `GuildMembers`, `MessageContent` y `GuildPresences`). |
| `CRYPTO_SECRET` | Una clave de cifrado de 32 caracteres utilizada para cifrar las claves de API almacenadas. |
| `POSTGRES_PASSWORD` | La contraseña de la base de datos. Todos los demás valores de `POSTGRES_*` se configuran automáticamente. |
| `ALLOW_PRIVATE_NETWORK` | `true` permite que funcionen los puntos de conexión personalizados y servidores MCP en tu máquina o LAN, una lista `host:port` permite únicamente esos servidores y `false` los bloquea. El bot no arrancará hasta que esté definido. Consulta [Redes privadas](/self-hosting/setup-wizard/#private-networks) para elegir. |

Genera un valor aleatorio de 32 caracteres para `CRYPTO_SECRET` usando Docker y luego cópialo en `.env`:

```sh
docker run --rm alpine:3.22 sh -c "head -c 24 /dev/urandom | base64"
```

Genera una contraseña separada para `POSTGRES_PASSWORD`. Puedes copiar ajustes de configuración opcionales desde `.env.optional.example`.

:::note[La conexión a la base de datos es automática]
No configures `POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_USER` ni `POSTGRES_DB` en `.env`; Compose los configura automáticamente.
:::

Prepara las carpetas de montaje en enlace del host antes de iniciar la pila:

<Tabs syncKey="operating-system">
<TabItem label="Windows">

```powershell
New-Item -ItemType Directory -Force -Path backups, logs, data | Out-Null
```

Docker Desktop mapea los directorios del host de Windows sin necesidad de `chown` de Unix.

</TabItem>
<TabItem label="Linux">

El contenedor del bot se ejecuta como UID 1001 y necesita acceso de escritura a los directorios `backups/`, `logs/` y `data/` del host. Créalos y asigna la propiedad antes del primer inicio:

```bash
mkdir -p backups logs data
sudo chown 1001:1001 backups logs data
```

Si ya ejecutaste Compose y Docker creó los directorios como root, ejecuta estos comandos después. No cambian la propiedad de los archivos que ya están dentro de los directorios.

</TabItem>
<TabItem label="Mac">

```bash
mkdir -p backups logs data
```

Docker Desktop en Mac mapea los montajes en enlace sin necesidad de `chown 1001:1001` de Unix.

</TabItem>
</Tabs>

## 3. Compila y ejecuta

```sh
docker compose build   # primera vez, o tras cambios de código o dependencias
docker compose up      # bot + base de datos
```

Para inicios posteriores, `docker compose up` por sí solo es suficiente a menos que cambies código o dependencias. Una vez que el bot se conecte a Discord, ejecuta `/setup` en cualquier canal del servidor para agregar tu clave de proveedor de IA. Consulta el [Inicio rápido](/introduction/quickstart/) para conocer las opciones de configuración en Discord.

Compose fija `RUN_ENV=development` en su definición de servicio para que funcionen los secretos de `.env` y los puntos de conexión HTTP locales. Los puntos de conexión locales como `http://host.docker.internal:11434` necesitan `ALLOW_PRIVATE_NETWORK` para permitirlos (`true`, o una lista que contenga `host.docker.internal:11434`); Docker Desktop proporciona `host.docker.internal` en Windows y Mac, y `docker-compose.yaml` también lo mapea a la puerta de enlace del host en Linux. Después de cambiar `.env`, ejecuta `docker compose up -d` para que el contenedor lo vuelva a leer. La comprobación de estado del contenedor informa si el proceso del bot está ejecutándose; no prueba la conectividad con la puerta de enlace de Discord.

## Configuración opcional de shards en un solo host

Deja `SHARD_COUNT` y `SHARD_IDS` sin definir para el comportamiento predeterminado: un solo proceso es dueño de todos los shards recomendados por Discord al iniciar. Las instalaciones pequeñas normalmente reciben un solo shard. Este modo no usa leases de shards ni escucha de invalidación de caché. Varios shards pueden compartir el mismo proceso.

Para ejecutar cuatro shards en el servicio existente, añade `SHARD_COUNT=4` a `.env` y deja `SHARD_IDS` sin definir. Añade esta anulación de servicio en `compose.override.yaml` para permitir que el apagado acotado termine de forma limpia:

```yaml
services:
  tomoribot:
    stop_grace_period: 40s
```

Vuelve a crear el servicio con `docker compose up -d --build tomoribot`. Si un script invoca `docker stop` o proporciona su propio tiempo de espera para detener Compose, permite al menos 40 segundos allí también. La selección automática no cambia la cantidad de shards mientras se ejecuta; modificar el total requiere un reinicio coordinado.

Los subconjuntos estáticos opcionales requieren un servicio independiente por grupo con el mismo `SHARD_COUNT` explícito y `SHARD_IDS` disjuntos, por ejemplo `0,1` y `2,3` con un total de `4`. Asigna a los servicios nombres estables distintos, nombres de contenedor distintos y los puertos de verificación de estado publicados que correspondan. La aplicación deriva etiquetas de métricas estables para cada grupo. Mantén una sola base de datos, ejecuta la inicialización puntual existente `bun run src/db/initializeCli.ts` con credenciales de gestión de esquema antes del inicio del gateway, y define `DATABASE_SCHEMA_MANAGEMENT_ENABLED=false` en cada proceso de gateway. No inicies el servicio original dueño de todos los shards junto con estos grupos. Detén los procesos anteriores antes de cambiar el total o la partición.

El modo de subconjuntos rechaza un puente de Matrix completamente configurado. Los límites por usuario para turnos y subidas siguen siendo por proceso, así que evalúa si ese margen multiplicado es aceptable antes de habilitar un segundo proceso. Las instalaciones que usan la facturación para supporters exclusiva de la rama release también requieren admisión compartida de gasto y coordinación de conciliación antes de atender solicitudes financiadas desde varios procesos. Consulta [sharding y propiedad de procesos](/architecture/subsystems/sharding/) para conocer los límites de seguridad y estado.

## 4. Servidores locales opcionales (perfiles de Compose)

Ejecuta servidores auxiliares locales opcionales con perfiles de Compose para que solo inicie lo que necesitas:

```sh
# SearXNG (búsqueda web privada) + Crawl4AI (obtención renderizada por navegador)
docker compose --profile searxng --profile fetch-crawl4ai up
```

Al habilitar SearXNG, configura `SEARXNG_BASE_URL=http://searxng:8080/` en `.env`. De lo contrario, déjalo sin configurar. Establece `SEARXNG_SECRET` en un valor aleatorio independiente para la firma de solicitudes de SearXNG.

Consulta [SearXNG](/self-hosting/local-endpoints/setup-searxng/), [Crawl4AI](/self-hosting/local-endpoints/setup-crawl4ai/) y [Monitoreo local](/self-hosting/local-monitoring/) para la configuración específica del servidor.

## Mantenimiento, actualización y copias de seguridad

Antes de actualizar, detén el bot y haz una copia de seguridad de tu base de datos y medios; consulta [Mantenimiento y copias de seguridad](/self-hosting/maintenance/). Luego descarga el código nuevo y reconstruye el contenedor:

```sh
git pull
docker compose up -d --build
```
