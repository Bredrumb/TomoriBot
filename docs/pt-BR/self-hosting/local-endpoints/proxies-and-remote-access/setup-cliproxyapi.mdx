Conecte o TomoriBot a um upstream autorizado por meio do [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI), um proxy local de Chat Completions.

:::caution[Use proxies de conta CLI por sua conta e risco]
O acesso de terceiros por meio do Codex, Claude Code, Antigravity ou outras contas de CLI pode violar os termos do provedor e gerar risco de suspensão da conta. Uma assinatura não garante permissão para uso de bot ou API. Revise as [restrições específicas de cada provedor e alternativas de API](/self-hosting/local-endpoints/proxies-and-remote-access/#account-risk) antes de fazer login. Os termos do Antigravity do Google proíbem explicitamente o acesso de terceiros por meio do Antigravity OAuth.
:::

## 1. Instale o CLIProxyAPI

1. Use a [versão estável mais recente](https://github.com/router-for-me/CLIProxyAPI/releases/latest) oficial. Os exemplos baixam o arquivo compactado e os checksums correspondentes juntos.
2. Abra um terminal em uma pasta vazia pertencente à sua conta:

Execute no PowerShell. No Windows ARM64, altere `windows_amd64` para `windows_aarch64`.

```powershell
$release = Invoke-RestMethod 'https://api.github.com/repos/router-for-me/CLIProxyAPI/releases/latest'
$asset = @($release.assets | Where-Object name -Like 'CLIProxyAPI_*_windows_amd64.zip')
$checksums = @($release.assets | Where-Object name -EQ 'checksums.txt')
if ($asset.Count -ne 1 -or $checksums.Count -ne 1) { throw 'Check the release assets before continuing' }
$archive = $asset[0].name
$release.tag_name
Invoke-WebRequest $asset[0].browser_download_url -OutFile $archive
Invoke-WebRequest $checksums[0].browser_download_url -OutFile checksums.txt
$expected = ((Select-String -Path checksums.txt -Pattern ([regex]::Escape($archive) + '$')).Line -split '\s+')[0]
if (!$expected -or (Get-FileHash $archive -Algorithm SHA256).Hash -ine $expected) {
  throw 'Archive checksum mismatch'
}
Expand-Archive -LiteralPath $archive -DestinationPath .\app
Set-Location .\app
.\cli-proxy-api.exe --help
```

## 2. Configure um listener local

1. Crie `config.yaml` ao lado do executável em um editor privado.
2. Substitua o marcador da chave de cliente por pelo menos 32 bytes aleatórios codificados em hex ou base64, gerados pelo seu gerenciador de senhas.
3. Restrinja esta pasta e o diretório de credenciais à sua conta e à conta do processo. Mantenha ambos fora do Git e de pastas compartilhadas.

```yaml
config-version: 8
server:
  host: "127.0.0.1"
  port: 8317
  discovery:
    enabled: false
management:
  allow-remote: false
  secret-key: ""
  disable-control-panel: true
access:
  api-keys:
    - "REPLACE_WITH_RANDOM_CLIENT_KEY"
oauth:
  auth-dir: "~/.cli-proxy-api"
```

- O segredo de gerenciamento vazio desativa `/v0/management` e `/v8/management`. Deixe `MANAGEMENT_PASSWORD` sem definição e evite `--password` e a TUI de gerenciamento.
- Mantenha o gerenciamento desativado atrás de um túnel: o conector também alcança o motor via loopback.

4. Adicione um backend autorizado. Para uma API compatível com OpenAI, mescle este bloco de nível superior separado com a URL, chave e ID do modelo reais:

```yaml
api-keys:
  openai-compatibility:
    - name: "authorized-backend"
      base-url: "https://api.example.com/v1"
      keys:
        - api-key: "REPLACE_WITH_UPSTREAM_KEY"
      models:
        - name: "upstream-model-id"
          alias: "home-chat"
```

| Local da chave | Finalidade |
|---|---|
| `access.api-keys` | O TomoriBot se autentica no CLIProxyAPI |
| `api-keys` de nível superior | O CLIProxyAPI se autentica no upstream |

Substitua todos os valores de exemplo e ative apenas o backend de que precisar.

### Alternativas de login com conta

- As flags disponíveis incluem Gemini CLI `--login`, Claude `--claude-login` e Codex `--codex-login` / `--codex-device-login`. `--help` lista as outras flags específicas de cada provedor.
- Use o login de conta apenas quando o provedor autorizar a ponte. Revise a tela de consentimento e as permissões solicitadas; os escopos variam conforme o provedor.
- Passe o mesmo caminho `--config` absoluto para os comandos de login e de servidor. As credenciais de atualização ficam armazenadas em `oauth.auth-dir`, aqui o diretório `.cli-proxy-api` do seu perfil.
- Mantenha os listeners temporários de callback OAuth locais. Para revogar o acesso, revogue-o nas configurações da conta upstream, pare o proxy e remova os arquivos locais de credenciais. Apagar os arquivos por si só não revoga tokens.
- `--antigravity-login` existe, mas entra em conflito com a restrição do Google acima. Nenhum procedimento de login do Antigravity é fornecido aqui; sua implementação solicita permissões amplas do Cloud Platform, perfil/e-mail, código de IA, registro e experimento/configuração.

## 4. Registre e selecione modelos

1. Execute `/providers` (gerenciadores do servidor) ou `/personal providers` (sua própria conexão).
2. Escolha `Adicionar Novo Endpoint Personalizado` e preencha:

| Campo | Valor |
|---|---|
| Rótulo do Endpoint | Um rótulo de conexão privado, como `home-proxy` |
| Compatibilidade de API | `Compatível com OpenAI` |
| URL do Endpoint, bot neste PC fora da produção | `http://127.0.0.1:8317/v1` |
| URL do Endpoint, bot de produção hospedado separadamente | A base HTTPS do relay autenticado, como `https://relay.example.net/v1`, após concluir o [guia do Cloudflare](/self-hosting/local-endpoints/proxies-and-remote-access/cloudflare-tunnel/) |
| Token de Autenticação | A chave de cliente do CLIProxyAPI; obrigatória nesta configuração |

3. Selecione o endpoint salvo, adicione um Modelo de Texto e insira o ID exato ou alias de `/v1/models`.
4. Deixe `Janela de Contexto` em branco e as opções de capacidade desativadas até testar. Mantenha o vídeo desativado.
5. Para usar outro modelo, adicione o ID dele no mesmo endpoint e selecione-o no painel de modelos. O TomoriBot consulta `/v1/models`, mas não importa a lista automaticamente.

- O desenvolvimento no mesmo host exige `ALLOW_PRIVATE_NETWORK=127.0.0.1:8317` no ambiente do TomoriBot.
- No Docker, o loopback identifica o contêiner, então ele não alcança o listener do host através do próprio `127.0.0.1`.
- A produção exige HTTPS público e respostas de DNS públicas. Conclua o [guia do Cloudflare Tunnel](/self-hosting/local-endpoints/proxies-and-remote-access/cloudflare-tunnel/) e implante o relay antes de registrar uma URL remota.

## Capacidades e solução de problemas

- Os testes locais de protocolo cobrem texto, streaming, uma chamada de função por rodada com continuação e JSON sem streaming. OAuth ao vivo, upstreams pagos, qualidade de visão e conformidade estrita de esquema não foram testados.
- O CLIProxyAPI aceita mensagens de sistema na porta 8317; nenhuma adaptação do ChatMock é necessária.
- Mantenha as ferramentas desativadas, a menos que o backend produza uma chamada por rodada. Lotes paralelos de ferramentas não são suportados.
- Modelos que exigem repetição de assinatura de raciocínio específica do provedor precisam de validação separada. O chat personalizado genérico não transporta vídeo nem usa a API Responses.

| Sintoma | Ação |
|---|---|
| `401` | Verifique a chave de cliente separadamente da chave upstream. |
| `404` | Use a base `/v1`, sem `/chat/completions`; verifique o ID do modelo. |
| Parâmetros rejeitados | Deixe `Janela de Contexto` em branco e o raciocínio em Automático; o TomoriBot já tenta novamente rejeições de parâmetros elegíveis antes do início da saída. Verifique os logs em busca de requisições degradadas antes de ativar ferramentas ou depender de controles de amostragem. |
| `403`, página de login em HTML ou erros de túnel | Conclua a [validação do Access e do relay](/self-hosting/local-endpoints/proxies-and-remote-access/cloudflare-tunnel/#validate-each-authentication-check). Um hostname direto do Access exige cabeçalhos extras que o painel do Discord não consegue fornecer. |
| O stream é interrompido | Verifique a suspensão do PC, cota do upstream, integridade do túnel e os limites de stream no guia do Cloudflare. |

Mantenha o log de requisições e depuração desativado, a menos que esteja diagnosticando uma reprodução local sem dados sensíveis. Faça a rotação de uma chave de cliente vazada no CLIProxyAPI, no endpoint salvo do TomoriBot e no relay de produção. Revogue credenciais upstream vazadas separadamente.
