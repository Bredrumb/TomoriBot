## Iniciando Servidores Locais com `bun run launch`

Em vez de iniciar os servidores locais manualmente, use `bun run launch`, que inicia os servidores solicitados, aguarda que estejam prontos e então lança o bot no modo de observação automaticamente:

```sh
# Apenas o bot, idêntico a bun run dev
bun run launch

# Com os contêineres Docker do SearXNG e Crawl4AI
bun run launch --searxng --crawl4ai

# Com o verificador de prosa slop-guard para Revisão de respostas
bun run launch --slopguard

# Com um servidor TTS local (o venv deve ser configurado primeiro — veja o guia de Text-to-Speech abaixo)
bun run launch --qwen3tts
bun run launch --fishs2
bun run launch --voxcpm2
bun run launch --cosyvoice3

# Veja todas as flags disponíveis
bun run launch --help
```

Flags disponíveis: `--searxng`, `--crawl4ai`, `--slopguard` (alias `--slop-guard`), `--qwen3tts`, `--chatterbox`, `--irodoritts`, `--voxcpm2`, `--fishs2`, `--cosyvoice3`, `--moss`, `--whisperx`

Os servidores baseados em Docker (`--searxng`, `--crawl4ai`, `--slopguard`) são criados na primeira execução e reutilizados nas execuções subsequentes. Os servidores TTS/STT em Python exigem que seu venv seja configurado uma vez de antemão; veja os guias individuais de configuração em [Text-to-Speech](/pt-BR/self-hosting/local-endpoints/text-to-speech/) e [Speech-to-Text](/pt-BR/self-hosting/local-endpoints/speech-to-text/).

Ctrl+C para o bot e qualquer processo de servidor em Python. Os contêineres Docker são intencionalmente mantidos em execução. Pare-os manualmente com `docker stop searxng`, `docker stop crawl4ai` ou `docker stop slop-guard` quando terminar.
