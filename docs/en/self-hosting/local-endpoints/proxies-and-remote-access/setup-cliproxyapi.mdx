Connect TomoriBot to an authorized upstream through [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI), a local Chat Completions proxy.

:::caution[Use CLI account proxies at your own risk]
Third-party access through Codex, Claude Code, Antigravity, or other CLI accounts may violate provider terms and risk account suspension. A subscription does not establish permission for bot/API use. Review the [provider-specific restrictions and API alternatives](/self-hosting/local-endpoints/proxies-and-remote-access/#account-risk) before signing in. Google's Antigravity terms explicitly prohibit third-party access through Antigravity OAuth.
:::

## 1. Install CLIProxyAPI

1. Use the official [latest stable release](https://github.com/router-for-me/CLIProxyAPI/releases/latest). The examples download its archive and matching checksums together.
2. Open a terminal in an empty folder owned by your account:

<TabItem label="Windows">

Run in PowerShell. On ARM64 Windows, change `windows_amd64` to `windows_aarch64`.

```powershell
$release = Invoke-RestMethod 'https://api.github.com/repos/router-for-me/CLIProxyAPI/releases/latest'
$asset = @($release.assets | Where-Object name -Like 'CLIProxyAPI_*_windows_amd64.zip')
$checksums = @($release.assets | Where-Object name -EQ 'checksums.txt')
if ($asset.Count -ne 1 -or $checksums.Count -ne 1) { throw 'Check the release assets before continuing' }
$archive = $asset[0].name
$release.tag_name
Invoke-WebRequest $asset[0].browser_download_url -OutFile $archive
Invoke-WebRequest $checksums[0].browser_download_url -OutFile checksums.txt
$expected = ((Select-String -Path checksums.txt -Pattern ([regex]::Escape($archive) + '$')).Line -split '\s+')[0]
if (!$expected -or (Get-FileHash $archive -Algorithm SHA256).Hash -ine $expected) {
  throw 'Archive checksum mismatch'
}
Expand-Archive -LiteralPath $archive -DestinationPath .\app
Set-Location .\app
.\cli-proxy-api.exe --help
```

## 2. Configure a local listener

1. Create `config.yaml` beside the executable in a private editor.
2. Replace the client-key placeholder with at least 32 random bytes encoded as hex or base64, generated by your password manager.
3. Restrict this folder and the credential directory to your account and the process account. Keep both out of Git and shared folders.

```yaml
config-version: 8
server:
  host: "127.0.0.1"
  port: 8317
  discovery:
    enabled: false
management:
  allow-remote: false
  secret-key: ""
  disable-control-panel: true
access:
  api-keys:
    - "REPLACE_WITH_RANDOM_CLIENT_KEY"
oauth:
  auth-dir: "~/.cli-proxy-api"
```

- The empty management secret disables `/v0/management` and `/v8/management`. Leave `MANAGEMENT_PASSWORD` unset and avoid `--password` and the management TUI.
- Keep management disabled behind a tunnel: its connector reaches the engine through loopback too.

4. Add one authorized backend. For an OpenAI-compatible API, merge this separate top-level block with its actual URL, key, and model ID:

```yaml
api-keys:
  openai-compatibility:
    - name: "authorized-backend"
      base-url: "https://api.example.com/v1"
      keys:
        - api-key: "REPLACE_WITH_UPSTREAM_KEY"
      models:
        - name: "upstream-model-id"
          alias: "home-chat"
```

| Key location | Purpose |
|---|---|
| `access.api-keys` | TomoriBot authenticates to CLIProxyAPI |
| Top-level `api-keys` | CLIProxyAPI authenticates to the upstream |

Replace all sample values and enable only the backend you need.

### Account login alternatives

- Available flags include Gemini CLI `--login`, Claude `--claude-login`, and Codex `--codex-login` / `--codex-device-login`. `--help` lists the other provider-specific flags.
- Use account login only when the provider authorizes the bridge. Review its consent screen and requested permissions; scopes vary by provider.
- Pass the same absolute `--config` path to login and server commands. Refresh credentials are stored in `oauth.auth-dir`, here your profile's `.cli-proxy-api` directory.
- Keep temporary OAuth callback listeners local. To retire access, revoke it in the upstream account settings, stop the proxy, and remove its local credential files. File deletion alone does not revoke tokens.
- `--antigravity-login` exists, but conflicts with the Google restriction above. No Antigravity sign-in procedure is provided here; its implementation requests broad Cloud Platform, profile/email, AI code, logging, and experiment/configuration permissions.

## 4. Register and select models

1. Run `/providers` (server managers) or `/personal providers` (your own connection).
2. Choose `Add New Custom Endpoint` and enter:

| Field | Value |
|---|---|
| Endpoint label | A private connection label such as `home-proxy` |
| API compatibility | `OpenAI-Compatible` |
| Endpoint URL, bot on this PC outside production | `http://127.0.0.1:8317/v1` |
| Endpoint URL, separately hosted production bot | The authenticated relay's HTTPS base, such as `https://relay.example.net/v1`, after completing the [Cloudflare guide](/self-hosting/local-endpoints/proxies-and-remote-access/cloudflare-tunnel/) |
| Auth token | The CLIProxyAPI client key; required by this configuration |

3. Select the saved endpoint, add a Text Model, and enter the exact ID or alias from `/v1/models`.
4. Leave Context Window Override blank and capability toggles off until tested. Keep video off.
5. To use another model, add its ID under the same endpoint, then select it in the model panel. TomoriBot probes `/v1/models` but does not import the list automatically.

- Same-host development needs `ALLOW_PRIVATE_NETWORK=127.0.0.1:8317` in TomoriBot's environment.
- In Docker, loopback identifies the container, so it cannot reach the host's listener through its own `127.0.0.1`.
- Production requires public HTTPS and public DNS answers. Complete the [Cloudflare Tunnel guide](/self-hosting/local-endpoints/proxies-and-remote-access/cloudflare-tunnel/) and deploy its relay before registering a remote URL.

## Capabilities and troubleshooting

- Local protocol fixtures cover text, streaming, one function call per round with continuation, and non-streaming JSON. Live OAuth, paid upstreams, vision quality, and schema compliance are untested.
- CLIProxyAPI accepts system messages on port 8317; no ChatMock workaround is needed.
- Keep tools off unless the backend produces one call per round. Parallel tool batches are unsupported.
- Models requiring provider-specific reasoning-signature replay need separate validation. Generic custom chat does not carry video or use the Responses API.

| Symptom | Action |
|---|---|
| `401` | Check the client key, separately from the upstream key. |
| `404` | Use the `/v1` base, without `/chat/completions`; check the model ID. |
| Rejected parameters | Leave context override blank and reasoning on Auto; TomoriBot already retries eligible parameter rejections before output starts. Check logs for degraded requests before enabling tools or relying on sampling controls. |
| `403`, HTML login page, or tunnel errors | Complete the [Access and relay validation](/self-hosting/local-endpoints/proxies-and-remote-access/cloudflare-tunnel/#validate-each-authentication-check). A direct Access hostname needs extra headers the Discord panel cannot supply. |
| Stream stops | Check PC sleep, upstream quota, tunnel health, and the stream limits in the Cloudflare guide. |

Keep request/debug logging off unless diagnosing a redacted local reproduction. Rotate a leaked client key in CLIProxyAPI, TomoriBot's saved endpoint, and the production relay. Revoke leaked upstream credentials separately.
