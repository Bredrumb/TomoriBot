Connect TomoriBot to an authorized upstream through [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI), a local Chat Completions proxy.

:::danger[Use CLI account proxies at your own risk]
Third-party access through Codex, Claude Code, Antigravity, or other CLI accounts may violate provider terms and risk account suspension. A subscription does not establish permission for bot/API use. Review the [provider-specific restrictions and API alternatives](/self-hosting/local-endpoints/proxies-and-remote-access/#account-risk) before signing in.
:::

## 1. Install CLIProxyAPI

Follow the official [quick start](https://help.router-for.me/introduction/quick-start). The [release archives](https://github.com/router-for-me/CLIProxyAPI/releases/latest) contain ready-to-run executables; choose your operating system and CPU, extract the archive, and verify its checksum. Building a Git clone is optional.

## 2. Create the configuration

Configure CLIProxyAPI before starting it. If the installer started a service, stop it first.

Create `config.yaml` beside the executable (`cli-proxy-api.exe` on Windows). A separate config folder is optional; these examples keep both files together. Replace the client-key placeholder with at least 32 random bytes encoded as hex or base64, generated by your password manager.

```yaml
config-version: 8
server:
  host: "127.0.0.1"
  port: 8317
  discovery:
    enabled: false
management:
  allow-remote: false
  secret-key: ""
  disable-control-panel: true
access:
  api-keys:
    - "REPLACE_WITH_RANDOM_CLIENT_KEY"
oauth:
  auth-dir: "~/.cli-proxy-api"
```

The client key under `access.api-keys` authenticates TomoriBot to CLIProxyAPI. Keep `config.yaml` and the `oauth.auth-dir` credential files private and out of Git. Restrict access to your account and the process account.

Leave `MANAGEMENT_PASSWORD` unset and avoid `--password` and the management TUI: the empty management secret keeps management routes disabled, including behind the tunnel. If your version uses a different config format, apply these settings to its bundled `config.example.yaml`.

## 3. Connect the upstream

Choose how CLIProxyAPI authenticates to the model provider. Both methods use the base configuration above.

<Tabs syncKey="upstream-auth">
<TabItem label="Account login (OAuth)">

Run the login command from the folder containing the executable and `config.yaml`. These examples use Antigravity; substitute your provider's flag and review its consent screen before signing in:

| Provider | Login flag |
|---|---|
| Antigravity | `--antigravity-login` |
| Claude | `--claude-login` |
| Codex | `--codex-login` or `--codex-device-login` |

<Tabs syncKey="operating-system">
<TabItem label="Windows">

```powershell
$configPath = (Resolve-Path .\config.yaml).Path
.\cli-proxy-api.exe --config $configPath --antigravity-login
```

</TabItem>
<TabItem label="Linux">

```bash
./cli-proxy-api --config "$(pwd)/config.yaml" --antigravity-login
```

</TabItem>
<TabItem label="Mac">

```bash
./cli-proxy-api --config "$(pwd)/config.yaml" --antigravity-login
```

Complete the browser sign-in and wait for the terminal to report success. CLIProxyAPI saves credentials in `oauth.auth-dir`; an OAuth-only setup needs no upstream API-key block. Keep OAuth callback listeners local and use the same config path for login and startup. Other login flags are listed in `--help` and the [upstream provider guides](https://help.router-for.me/introduction/quick-start).

</TabItem>
<TabItem label="Upstream API key">

For an OpenAI-compatible API, add this top-level block to `config.yaml` and replace the sample URL, upstream key, and model ID:

```yaml
api-keys:
  openai-compatibility:
    - name: "authorized-backend"
      base-url: "https://api.example.com/v1"
      keys:
        - api-key: "REPLACE_WITH_UPSTREAM_KEY"
      models:
        - name: "upstream-model-id"
          alias: "home-chat"
```

</TabItem>
</Tabs>

## 5. Connect TomoriBot

<Tabs syncKey="bot-location">
<TabItem label="Bot on this PC">

1. For a non-production bot running on the same computer as CLIProxyAPI, set `ALLOW_PRIVATE_NETWORK=127.0.0.1:8317` in TomoriBot's environment and restart the bot. Use the local listener configured above; no tunnel is needed.
2. Run `/providers` (server managers) or `/personal providers` and add an `OpenAI-Compatible` custom endpoint with these settings:

| Field | Value |
|---|---|
| Endpoint URL | `http://127.0.0.1:8317/v1` |
| Auth token | The client key from `access.api-keys` |

Select the saved connection, add a Text Model using an ID or alias served by CLIProxyAPI, and confirm a Discord reply.

This URL assumes the bot runs directly on the host. In Docker, `127.0.0.1` identifies the container, so it cannot reach the host's listener through that address. A bot running in production mode still requires the hosted-production route.

</TabItem>
<TabItem label="Hosted production bot">

1. Complete [Cloudflare Tunnel](/self-hosting/local-endpoints/proxies-and-remote-access/cloudflare-tunnel/) using the text-engine profile and port 8317. Production requires a public HTTPS URL and public DNS answers.
2. Run `/providers` (server managers) or `/personal providers` and add an `OpenAI-Compatible` custom endpoint with these settings:

| Field | Value |
|---|---|
| Endpoint URL | Your tunnel's base, such as `https://engine.example.com/v1` |
| Auth token | The client key from `access.api-keys` |

Select the saved connection, add a Text Model using an ID or alias served by CLIProxyAPI, and confirm a Discord reply.

</TabItem>
</Tabs>

<details>
<summary>How to list available models</summary>

With CLIProxyAPI running, open another terminal to list its model IDs. Disable PowerShell transcripts or shell tracing before loading the client key. Close this terminal when finished.

<Tabs syncKey="operating-system">
<TabItem label="Windows">

Run this from the folder containing `config.yaml`; it reads the first client key from the layout above.

```powershell
$keyMatch = [regex]::Match((Get-Content -LiteralPath .\config.yaml -Raw), '(?m)^access:\r?\n  api-keys:\r?\n    - "([A-Za-z0-9+/=_-]+)"[ \t]*\r?$')
if (!$keyMatch.Success) { throw 'Expected a quoted client key under access.api-keys in config.yaml.' }
$engineKey = $keyMatch.Groups[1].Value
$headers = @{ Authorization = "Bearer $engineKey" }
$base = 'http://127.0.0.1:8317/v1'
$models = Invoke-RestMethod "$base/models" -Headers $headers
$models.data | Select-Object id
Remove-Variable engineKey, keyMatch, headers
```

</TabItem>
<TabItem label="Linux">

The key is read without echo and passed to curl through stdin, keeping it out of process arguments.

```bash
set +x
printf 'CLIProxyAPI client key: '
read -r -s engine_key
printf '\n'
base='http://127.0.0.1:8317/v1'
printf 'header = "Authorization: Bearer %s"\n' "$engine_key" |
  curl --config - --fail --silent --show-error "$base/models"
unset engine_key
```

</TabItem>
<TabItem label="Mac">

The key is read without echo and passed to curl through stdin, keeping it out of process arguments.

```bash
set +x
printf 'CLIProxyAPI client key: '
read -r -s engine_key
printf '\n'
```

An empty list needs upstream configuration. HTTP `401` means the server answered but rejected the client key.

## Troubleshooting

| Symptom | Action |
|---|---|
| `401` | Check the client key, separately from the upstream key. |
| `404` | Use the `/v1` base, without `/chat/completions`; check the model ID. |
| Rejected parameters | Leave context override blank and reasoning on Auto; TomoriBot already retries eligible parameter rejections before output starts. Check logs for degraded requests before enabling tools or relying on sampling controls. |
| `403`, HTML login page, or tunnel errors | Check [tunnel setup](/self-hosting/local-endpoints/proxies-and-remote-access/cloudflare-tunnel/). If you enabled Cloudflare Access, it needs the [optional Access and Caddy setup](/self-hosting/local-endpoints/proxies-and-remote-access/cloudflare-access-and-caddy/); the Discord panel cannot supply Access headers directly. |
| Stream stops | Check PC sleep, upstream quota, tunnel health, and the stream limits in the Cloudflare guide. |

Keep request/debug logging off unless diagnosing a redacted local reproduction. Rotate a leaked client key in CLIProxyAPI and TomoriBot's saved endpoint, plus any optional relay using it. Revoke leaked upstream credentials separately.

<details>
<summary>Retire an account login</summary>

Revoke access in the upstream account settings, stop the proxy, and remove its local credential files. File deletion alone does not revoke tokens.

</details>

<details>
<summary>Check the local binding address</summary>

If the local API is unreachable, check its binding address from another terminal while CLIProxyAPI is running:

<Tabs syncKey="operating-system">
<TabItem label="Windows">

```powershell
Get-NetTCPConnection -LocalPort 8317 |
  Select-Object LocalAddress, LocalPort, State, OwningProcess
```

</TabItem>
<TabItem label="Linux">

```bash
ss -ltnp 'sport = :8317'
```

</TabItem>
<TabItem label="Mac">

```bash
lsof -nP -iTCP:8317 -sTCP:LISTEN
```

</TabItem>
</Tabs>

Expect only `127.0.0.1`; stop if you see `0.0.0.0`, `::`, `*`, or a LAN address. Review existing firewall rules (`wf.msc` on Windows); do not open an inbound port or add router port forwarding. Windows TCP-state reporting can miss a reachable endpoint, so the query includes all states; the optional model lookup tests API reachability.

</details>

If a model fails to reply in Discord, test it directly while CLIProxyAPI is running. Disable PowerShell transcripts or shell tracing before loading the client key.

<Tabs syncKey="operating-system">
<TabItem label="Windows">

Run this from the folder containing `config.yaml`; it reads the first client key from the layout above.

```powershell
$keyMatch = [regex]::Match((Get-Content -LiteralPath .\config.yaml -Raw), '(?m)^access:\r?\n  api-keys:\r?\n    - "([A-Za-z0-9+/=_-]+)"[ \t]*\r?$')
```
