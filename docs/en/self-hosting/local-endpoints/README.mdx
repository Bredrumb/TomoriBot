## Starting Local Servers with `bun run launch`

Instead of starting local servers manually, use `bun run launch` which starts the requested servers, waits for them to be ready, then launches the bot in watch mode automatically:

```sh
# Bot only, identical to bun run dev
bun run launch

# With the SearXNG and Crawl4AI Docker containers
bun run launch --searxng --crawl4ai

# With the slop-guard prose linter for Response Drafting
bun run launch --slopguard

# With a local TTS server (venv must be set up first — see the Text-to-Speech guide below)
bun run launch --qwen3tts
bun run launch --fishs2
bun run launch --voxcpm2
bun run launch --cosyvoice3

# See all available flags
bun run launch --help
```

Available flags: `--searxng`, `--crawl4ai`, `--slopguard` (alias `--slop-guard`), `--qwen3tts`, `--chatterbox`, `--irodoritts`, `--voxcpm2`, `--fishs2`, `--cosyvoice3`, `--moss`, `--whisperx`

Docker-backed servers (`--searxng`, `--crawl4ai`, `--slopguard`) are created on first run and reused on subsequent runs. Python TTS/STT servers require their venv to be set up once beforehand; see the individual setup guides under [Text-to-Speech](/self-hosting/local-endpoints/text-to-speech/) and [Speech-to-Text](/self-hosting/local-endpoints/speech-to-text/).

`Ctrl+C` stops the bot and any Python server processes. Docker containers are intentionally left running. Stop them manually with `docker stop searxng`, `docker stop crawl4ai`, or `docker stop slop-guard` when done.
