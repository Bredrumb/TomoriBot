这是给不想用引导式向导的技术用户准备的手动安装流程。如果你想要一步一步带做的那种，请改用[安装向导](/self-hosting/setup-wizard/)，它会替你创建`.env`、生成安全的`CRYPTO_SECRET`、配置PostgreSQL，并运行安装。

## 环境要求

- [Bun](https://bun.sh/)
- PostgreSQL，可以原生安装，也可以跑在Docker容器里（见第2步）

PostgreSQL的数据表结构、`pgcrypto`、种子数据和迁移都会在bot启动时自动初始化。

## 1. 安装

```sh
git clone https://github.com/Bredrumb/TomoriBot.git
cd TomoriBot
bun install --frozen-lockfile
```

## 2. 配置

根据示例创建环境文件并填写所需的值：

<Tabs syncKey="operating-system">
<TabItem label="Windows">

```powershell
Copy-Item .env.example .env
```

</TabItem>
<TabItem label="Linux">

```bash
cp .env.example .env
```

</TabItem>
<TabItem label="Mac">

```bash
cp .env.example .env
```

</TabItem>
</Tabs>

必需的：

- `DISCORD_TOKEN`：你的Discord bot令牌（启用`GuildMembers`、`MessageContent`和`GuildPresences`特权intent）。
- `CRYPTO_SECRET`：32个字符的加密密钥（用于加密存储的API密钥）。
- PostgreSQL连接：`POSTGRES_HOST`、`POSTGRES_PORT`、`POSTGRES_USER`、`POSTGRES_PASSWORD`、`POSTGRES_DB`。
- `ALLOW_PRIVATE_NETWORK`：`true`、`false`或`host:port`列表。如何选择请参见[私有网络](/self-hosting/setup-wizard/#private-networks)。

请将加密密钥的受保护副本与数据库备份分开保存。新的备份不包含`.env`。对于密钥轮换，请使用`CRYPTO_SECRET_V1`、`CRYPTO_SECRET_V2`或任何后续的正整数版本，并可选择使用`CRYPTO_SECRET_CURRENT`。

:::note[没有原生PostgreSQL？]
仅在容器中运行数据库，然后将`POSTGRES_*`值指向它：

```sh
docker run -d --name tomori-db \
  -e POSTGRES_USER=tomori -e POSTGRES_PASSWORD=yourpassword -e POSTGRES_DB=tomori \
  -p 5432:5432 pgvector/pgvector:pg16
```

然后设置`POSTGRES_HOST=localhost`、`POSTGRES_PORT=5432`，以及上面的用户/密码/数据库名。`pgvector/pgvector`镜像预装了RAG扩展；如果不需要文档/RAG记忆，可以换成`postgres:16`。这种方式只在Docker里运行数据库，bot本身仍然运行在宿主机的Bun上。如果想让bot和数据库都完全容器化，请改用[Docker Compose](/self-hosting/docker-compose/)。
:::

`.env.optional.example`中有可选的调优设置。复制任何你想自定义的值（限制、超时、功能开关、本地服务器URL等）。

请把`data/`目录放在持久化存储上。本地文件可能包括位于`data/avatars/`的人格头像与立绘、位于`data/voice-samples/`的语音样本，以及位于`data/custom-expressions/`的自定义表情。数据库单独存储，因此请将这些文件一并备份。

## 3. 运行

```sh
bun run dev
```

当你看到`TomoriBot up and running!`时，去Discord在你的服务器里运行`/setup`，接入AI提供方并初始化bot。该指令会打开一个引导式清单面板，在你按下`完成设置`之前不会写入任何内容。

如果你想让可选的本地服务器（SearXNG、Crawl4AI、本地TTS/STT）与bot一起启动，请用`bun run launch`代替`bun run dev`：

```sh
bun run launch --searxng --crawl4ai
bun run launch --help        # see all flags
```

## 可选附加项（手动版的「完整安装」）
{/* anchor: optional-extras-the-manual-full-install */}

[安装向导](/self-hosting/setup-wizard/)的`Full Install`路径会在基础安装之上叠加若干轻量附加项。它们都不是运行bot的必需项，但每一项都会解锁一个功能。如果你是手动安装，想加哪个就加哪个：

### `pgvector`：文档与RAG记忆

RAG（文档上传与跨频道回忆）会把嵌入向量存进`vector`列，这需要[pgvector](https://github.com/pgvector/pgvector)扩展。

<Tabs syncKey="operating-system">
<TabItem label="Windows">

原生的Windows PostgreSQL没有预编译的`pgvector`安装包。原生安装需要针对你的确切PostgreSQL版本，用Visual Studio C++和`nmake`从源码编译（见pgvector的[Windows说明](https://github.com/pgvector/pgvector#windows)）。Windows上更简单的路子是把PostgreSQL跑在[配置](#2-配置)一节中展示的`pgvector/pgvector`容器里，然后在容器内打开`psql`：

```powershell
docker exec -it tomori-db psql -U tomori -d tomori
```

如果你为原生Windows PostgreSQL编译了`pgvector`，则改为直接使用`psql`连接：

```powershell
psql -h localhost -p 5432 -U tomori -d tomodb
```

</TabItem>
<TabItem label="Linux">

按你的PostgreSQL主版本安装`pgvector`包（以下为PostgreSQL 16在Debian/Ubuntu上的示例）：

```bash
sudo apt-get install -y postgresql-16-pgvector
```

使用`psql`连接到数据库（如果运行在Docker中，则使用`docker exec -it tomori-db psql -U tomori -d tomori`）：

```bash
psql -h localhost -p 5432 -U tomori -d tomodb
```

</TabItem>
<TabItem label="Mac">

通过Homebrew安装与Homebrew中PostgreSQL配方对应的`pgvector`（如果你固定了较旧的PostgreSQL配方且预编译bottle不匹配，请针对该配方的`pg_config`执行`make && make install`从源码编译`pgvector`）：

```bash
brew install pgvector
```

使用`psql`连接到数据库（如果运行在Docker中，则使用`docker exec -it tomori-db psql -U tomori -d tomori`）：

```bash
psql -h localhost -p 5432 -U tomori -d tomodb
```

</TabItem>
</Tabs>

连接后（`psql`会提示输入`POSTGRES_PASSWORD`），启用该扩展：

```sql
CREATE EXTENSION vector;
```

没有pgvector，bot照样能跑，但RAG功能会完全不可用。还原备份之前，目标数据库上也必须装好这个扩展；细节见[维护与备份](/self-hosting/maintenance/)。

### `pg_cron`：定时清理任务

`pg_cron`支撑可选的周期性数据库维护（冷却行与提醒行的清理）。本仓库的Docker Compose已经替你配置好了。

:::caution[提醒和触发并不需要它]
`pg_cron`纯粹是打扫卫生，它只清理过期数据行。提醒的发送与随机触发都在应用内部运行，所以有没有`pg_cron`这些功能都照常工作。
:::

对于自己管理的PostgreSQL，如果需要，请先安装扩展包，再在`postgresql.conf`中加载它：

<Tabs syncKey="operating-system">
<TabItem label="Windows">

原生Windows PostgreSQL没有标准的`pg_cron`预编译二进制包；需要针对你的PostgreSQL服务端头文件使用Visual Studio C++（`nmake`）编译，或者改用[Docker Compose](/self-hosting/docker-compose/)或WSL2 Linux来运行PostgreSQL。因为`pg_cron`只清理过期数据行，跳过它不会影响bot的任何功能。

</TabItem>
<TabItem label="Linux">

按你的PostgreSQL主版本安装`pg_cron`包（以下为PostgreSQL 16在Debian/Ubuntu上的示例）：

```bash
sudo apt-get install -y postgresql-16-cron
```

</TabItem>
<TabItem label="Mac">

通过Homebrew安装与Homebrew中PostgreSQL配方对应的`pg_cron`：

```bash
brew install pg_cron
```

</TabItem>
</Tabs>

在`psql`中找到生效中的配置文件：

```sql
SHOW config_file;
```

在`postgresql.conf`里启用该扩展：如果`shared_preload_libraries`已经列了其他库，就追加进去：

```ini
shared_preload_libraries = 'pg_cron'   # e.g. 'pg_stat_statements,pg_cron'
cron.database_name = 'your_dbname'
```

重启PostgreSQL，然后：

```sql
CREATE EXTENSION IF NOT EXISTS pg_cron;
```

### 分词器资源

NovelAI文本生成与感知模型的词元偏置需要本地分词器资源：

```sh
bun run setup:tokenizers
```

有些模型家族（例如Gemma）是受限的，需要你先接受它们的许可，再使用一个[HuggingFace令牌](https://huggingface.co/settings/tokens)：

<Tabs syncKey="operating-system">
<TabItem label="Windows">

```powershell
$secureToken = Read-Host -Prompt "Hugging Face token" -AsSecureString
$env:HF_TOKEN = [System.Net.NetworkCredential]::new("", $secureToken).Password
try {
  bun run setup:tokenizers
} finally {
  Remove-Item Env:\HF_TOKEN -ErrorAction SilentlyContinue
}
```

</TabItem>
<TabItem label="Linux">

```bash
read -r -s -p "Hugging Face token: " HF_TOKEN
echo
HF_TOKEN="$HF_TOKEN" bun run setup:tokenizers
unset HF_TOKEN
```

</TabItem>
<TabItem label="Mac">

```bash
printf 'Hugging Face token: '
read -r -s HF_TOKEN
echo
HF_TOKEN="$HF_TOKEN" bun run setup:tokenizers
unset HF_TOKEN
```

</TabItem>
</Tabs>

缺失资源会禁用可选的词元偏置。NovelAI文本生成需要其三个分词器家族，如果缺失或无效将返回设置错误。这些家族使用固定的公开MIT定义，无需Hugging Face令牌。如需仅安装这些家族：

```sh
bun run setup:tokenizers --family novelai_nerdstash_v2
bun run setup:tokenizers --family novelai_llama3
bun run setup:tokenizers --family novelai_glm
```

下载器会将文件写入仓库的`tokenizers/`目录。如果`TOKENIZER_ASSET_DIR`指向其他位置，请将下载的家族目录复制到该处。在安装或修复资源后请重启TomoriBot，因为运行时会缓存加载失败状态。

安全的`fetch_url`回退和DuckDuckGo的`web_search`回退均在进程内运行，因此两者都不需要额外安装。

## 维护、更新与备份

装好之后，宿主机端脚本（`bun run update`、`bun run backup`、`bun run restore-backup`、`bun run nuke-db`、`bun run rotate-keys`等）以及更新和备份流程，都写在[维护与备份](/self-hosting/maintenance/)页面。如果你准备拉取新版本，请先看[维护与备份](/self-hosting/maintenance/)。
