NovelAI 连接了文本模型（`GLM 4.6`、`Xialong`、`Kayra`、`Erato`）与动漫图像生成。你可以将两者都交给 NovelAI 处理，也可以将其图像生成与其他聊天提供方搭配使用。

## 文本模型与订阅
<!-- anchor: text-models-and-subscription -->

`GLM 4.6` 是默认文本模型。`Xialong` 与 `Erato` 需要有效的 Opus 订阅。选择 `Xialong` 会检查你保存的服务器或个人密钥；如果在添加密钥前选择了它，检查会在你添加密钥时运行。提供服务的密钥订阅等级决定了上下文额度。服务器管理员可以使用 `/novelai usage` 查看 Opus 生成额度。

NovelAI 的 [Chat Format 指南](https://docs.novelai.net/en/text/chatformat/) 说明了用于 `Kayra` 与 `Erato` 的故事风格方案；`GLM 4.6` 和 `Xialong` 则使用独立的聊天模板。下方的过滤与润色是 TomoriBot 自身的适配处理。

## 采样预设集
<!-- anchor: sampling-presets -->

切换文本模型会为所选模型加载 `Carefree-Kayra`、`Erato-Shosetsu` 或 `Default-Xialong`；`GLM 4.6` 则使用其自带的默认值。切换会重置温度、top-k、top-p 与 min-p，并为服务器和个人模型切换启用这些采样器。可以在 `/config` > `模型` > `文本采样器与参数` 中修改预设集或采样器；之后的修改会保持有效，在同一模型上更换密钥也会保留它们。

## 上下文与设置
<!-- anchor: context-and-settings -->

省略的设置仍会保存在 `/config` > `行为` > `常规行为` 中，以供其他提供方使用。

| 内容或设置 | NovelAI 的处理方式 |
|---|---|
| 人格属性、示例对话、对话记录以及记忆 | 保留，包括可见的个人记忆与短期记忆。隐私与记忆标签过滤依然生效。 |
| 系统、人格与频道提示词；上下文提醒；回复自然度规则；奖励与惩罚；SillyTavern 指令 | 省略。Xialong 使用 NovelAI 的系统提示词；GLM、Kayra 和 Erato 没有系统区块。 |
| 状态、时间/频道/服务器信息、文档，以及表情/贴纸/立绘清单 | 省略。 |
| 记忆工具提示 | 省略，包括在个人覆盖或备用切换前构建的提示。 |
| ATTG 元数据与质量星级 | ATTG 代表 Author（作者）、Title（标题）、Tags（标签）和 Genre（题材）。Xialong 会将元数据放在其持久信息的首位，并默认设为 4 星。Erato 使用配置的星级；Kayra 则省略星级。 |
| 回复前缀 | 在回复前缀控制允许时予以保留。 |
| 工具与媒体 | 文本模型无法调用工具，也不支持图像/视频输入。斜杠指令与单独的图像生成指令依然可用。 |
| Token 限制 | 在本地计算并预留回复空间。配置的回复长度优先于预设集长度，且可能会被缩减以容纳上下文。 |

即使关闭了共用的说话人停止设置，已知的其他说话人标签以及单独成行的 `---` 或 `***` 也会停止输出。正在回复的人格的名称、别名与立绘标签依然允许出现。本地防护会保护代码；字面 API 停止词在生成的代码内部仍可能匹配。

## 上下文裁剪
<!-- anchor: context-trimming -->

记忆最多占用上下文窗口的 20%，较早的条目会先被移除。如果提示词仍然无法容纳，TomoriBot 会按以下顺序进行裁剪：

| 顺序 | 移除的内容 | 受保护的内容 |
|---|---|---|
| 1 | 多余的示例对话 | 保留一组可用的示例对话回合 |
| 2 | 记忆（优先移除较早条目） | 无最低限制 |
| 3 | 较早的对话历史 | 最多保留两组近期的历史回合 |

人格属性、ATTG 元数据以及当前回合也同样受保护。如果受保护的上下文仍无法容纳，生成将失败。裁剪不会修改已保存的记忆与消息。

`/tool prompt snapshot` 可以显示最终的提示词、token 计数、回复上限与裁剪报告。

## 文本润色与 Discord 发送
<!-- anchor: text-polishing-and-discord-delivery -->

润色仅在计算 token 之前修改发送给全部四种 NovelAI 模型的历史记录、记忆与示例对话的副本。已保存的文本与其他提供方不受影响；语法不会被重写。

- **文本正确大写**：拉丁句首和行首字母大写；已知人格名称使用其配置的大小写。
- **正文行补全标点**：补充缺失的句末句号，同时保留现有的标点、换行与空行。
- **格式化正文获得润色**：`*kisses juno*` 会变为 `*Kisses Juno.*`。粗体、下划线、删除线与防剧透遮罩遵循相同规则；行内强调除名称外保持原有大小写。
- **代码与标记保持原样**：代码、URL、提及、Discord 标记、列表、标题、引用块、表格与分隔线均保留其内容或结构。
- **遵循非正文的开头与结尾**：以代码块、URL、提及、表情或非拉丁字母开头的行会跳过句子格式化。表情、颜文字、代码与链接结尾不会添加多余句号。
- **长期记忆采用纯文本内容**：省略附加的所有者标签、数据库 ID 与标签前缀；保留解析后的名称。
- **移除生成的历史记录注解**：省略回复引用、反应元数据与管理提示。手势转化为动作；场景与总结去除系统包装。包含 `System:` 的字面用户文本会被保留。
- **回复前缀保持精准**：明确的回复前缀与续写片段保持不变。
- **Discord 发送遵循你的设置**：回复自然度依然控制大小写、标点与消息拆分。后续历史记录会再次被润色；丢失的标点无法完全精确恢复。

## 图像生成
<!-- anchor: image-generation -->

在 `/config` > `模型` > `切换模型` 下为 `NovelAI 图像` 槽位分配模型。成员可以直接使用 `/novelai generate image` 生成图像，也可以在当前活动文本提供方支持工具调用时在聊天中提出请求。

`Default + Image Generation Expert` 预设集为 NovelAI 使用图像板（imageboard）风格的标签，并在需要互动或文字排版时辅以简短描述。对于多角色场景，TomoriBot 会将共用场景与镜头指令同每个角色的外貌与动作分离开来。

如需清晰易读的台词，请让 TomoriBot 包含确切的对话内容。NovelAI 图像工具会自动将角色对话放在尾部的 `Text:` 区块中。V4 与 V4.5 支持英文文本；V5 还支持日文与中文。招牌或屏幕上的文字可以在共用场景提示词中进行描述。请保持请求的文本简短，并避免在正向标签中加入 `no text`。排版与文字位置（包括日文纵排）属于建议而非绝对保证。
