对话记录是一项需主动开启的功能。它仅供你个人使用，用于保存你在服务器中所发消息周围的上下文摘录。在存储前，Discord 的结构化身份标识会被替换为占位符（自由文本和外部链接仍可能识别出个人身份）。

**默认情况下，TomoriBot 不会保存你的消息。记录功能为每位用户可选且仅供个人使用，只有在确认 `/record` 指令后才会启动。TomoriBot 绝不会自动利用这些摘录构建人格、发起 AI 提供方调用或向任何训练流程输送数据。**

## 它的用途

- 保存你自己的服务器消息及周边上下文的个人档案。
- 借助时间戳、消息顺序和回复关联回顾以往的讨论。
- 回顾你自己的行文风格，以便在离线下起草人格设定笔记或提示词。
- 导出结构化的 Markdown 或 JSON 记录文本供个人离线使用。

## 开始与停止记录

- **`/record start`**：选择记录时长，以及仅保存自己的消息还是包含周围消息，然后确认。除非你计划手动停止，否则请避免选择 `直到手动停止（不推荐）`。
- **进行中的会话**：在每个服务器中你只能维持一个进行中的记录会话。在记录处于活动状态时运行 `/record start` 将打开其设置：上下文范围的变更仅对新摘录生效；更改时长会从当前开始重新设定结束时间，而保持相同时长则会保留当前的结束时间。
- **`/record stop`**：停止收集并保留已保存的摘录。
- **`/record data`**：打开你在当前服务器中的记录与设置。
- **范围限制**：私信中不可用。服务器管理者无法查看、导出或删除你的记录。

## 保存的内容

- **触发机制**：开启后，你发送的每条真实消息均可触发保存一段以该消息结尾的摘录（即使 Tomori 没有回复也是如此）。通过扮演功能发送的消息不会触发记录。
- **上下文范围**：从有限的近期时间窗口内获取同频道或子区中最多 10 条较早且符合条件的消息（它们的时间可能早于开启时刻）。
- **模式**：`仅我的消息` 仅保存你本人的消息。`包含周围消息` 还可保存其他成员、bot 及 Webhook 的消息，即使对方从未开启过记录。
- **符合条件的频道**：你和 bot 均有权查看并读取历史消息的服务器频道与子区，包括受限频道和私密子区。隐私等级设为「完全」的成员会被跳过。频道私密设置和跨频道上下文设置不会排除你的记录。
- **间隔与重复**：摘录是带有时间戳、顺序和回复关联的相互重叠的快照。同一条消息可能会出现在多段摘录中。停机、遗漏事件或缺少权限会导致记录中出现缺口（不会回溯填补）。
- **嵌入内容**：将嵌入标题、描述、字段、作者名称和页脚作为消息正文保存，并套用与普通文本相同的身份标识替换规则。
- **附件**：仅保存图像、视频、音频和文件的数量（未知类型按文件计）。媒体文件的具体内容字节、文件名、附件 URL、OCR 文本及生成的媒体描述均不会保存。

### 可读的身份占位符

- 结构化的提及、频道与身份组使用会话内稳定的占位符（`[SELF]`、`[PARTICIPANT_1]`、`[CHANNEL_1]`、`[ROLE_1]`）。
- 唯一已知的名称和昵称在保存前会不区分大小写地替换（这也可能会替换掉与名称相吻合的普通单词）。重名会被跳过，且不会进行全服务器范围的搜索。
- Discord 自定义表情会转为 `:name:`；Unicode 表情保持原样。Discord 消息链接会转为通用标记；外部 URL 保持原样。
- 替换遵循最大努力原则：自由文本和外部链接仍可能识别出个人身份。用户自行输入的形似占位符的文本将保持字面文本。

## 导出与删除

- **导出**：在 `/record data` 中，选择时间范围以及 Markdown 或 JSON 格式。相对时间范围以你提交请求的时刻为截止；`全部时间` 包含所有已保存的摘录。摘录是根据其末尾消息的时间进行筛选的。
- **交付方式**：文件将以私密回复的形式发送（请在回复过期前及时保存）。文件名包含 UTC 导出时间及简短导出 ID；分卷文件还会包含分部编号。大型导出会在完整摘录之间进行分卷；若时间范围或单条摘录超出大小限制，请缩小所选范围。即使你日后失去了源频道的访问权限，已保存的摘录依然可以导出。
- **JSON ID**：每次导出都会分配全新的不透明 ID（在各分卷文件中，同一条消息会保留相同的 ID；文本相同的不同消息则获得不同 ID）。不会导出任何 Discord ID 或数据库内部存储 ID。
- **删除**：点击 `删除服务器记录` 选择时间范围（包括 `全部时间`），然后确认。时间范围以提交选择的时刻为截止；此后记录的消息仍会保留。删除操作不会停止当前活动的记录，停止记录也不会删除已保存的记录。

## 隐私与保留

- **运维人员访问与 AI**：bot 运维人员会将记录存储在其数据库中，并可能拥有基础设施层面的访问权限。记录功能绝不会发起任何 AI 提供方调用，也不会启动任何训练或模仿流程。
- **配额**：在所有服务器中共享 100 MiB 的逻辑记录文本内容（共享消息在每条摘录中单独计入）。配额占满时，会优先逐出你在各服务器中最旧的完整摘录。
- **保留期限**：自动按时长过期功能默认关闭，除非运维人员配置了 `RECORD_RETENTION_DAYS`。该设置会根据整条摘录末尾消息的时间，使整条摘录过期（包含已有记录）。
- **编辑与删除**：观察到的源消息编辑会更新存储的文本和附件计数；观察到的删除以及后续的隐私排除规则会移除已存储的副本。离线或无法访问期间发生的事件无法被监测到，且已下载的文件或备份不受影响。请参阅[隐私政策](/legal/privacy-policy/)以及[记录维护](/self-hosting/maintenance/#conversation-recording-storage)。
