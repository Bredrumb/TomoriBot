TomoriBot可以使用任何OpenAI相容的本機LLM伺服器進行文字生成與嵌入。

:::note[不需要環境變數]
本機模型透過Discord斜線指令註冊，並加密儲存在資料庫中。它們沒有`.env`設定。
:::

## 1. 執行你的模型伺服器

本指南以Ollama為例逐步說明，因為它最容易上手；你也可以使用任何你想要的伺服器，特別是如果你已經具備更多技術背景！

安裝[Ollama](https://ollama.com)。底下的範例使用Google的Gemma 4，但[Ollama的模型庫](https://ollama.com/library)中任何模型都可以使用。

### 我該拉取哪種大小？
{/* anchor: which-size-should-i-pull */}

本機模型執行在你的GPU VRAM（或Mac上的Apple Silicon統一記憶體）中。經驗法則：模型至少需要等於其下載大小的可用記憶體，再加上約1到2GB的餘裕給對話脈絡。挑選適合你硬體的最大Gemma 4：

| 可用VRAM / GPU記憶體 | 最合適 | 下載大小（約） |
|---|---|---|
| ~8GB | `gemma4:e2b` | 7.2GB |
| ~12GB | `gemma4:12b` | 7.6GB |
| ~16GB | `gemma4:12b`（可完整容納）或`gemma4:26b` | 7.6 / 18GB |
| 24GB+ | `gemma4:26b`或`gemma4:31b` | 18 / 20GB |

下載大小是Ollama預設量化的大小；確切數值請參閱[模型頁面](https://ollama.com/library/gemma4)。

如何查看你的GPU記憶體、在Ollama尚未作為背景服務執行時啟動它，並確認它有回應：

<Tabs syncKey="operating-system">
<TabItem label="Windows">

開啟`工作管理員` > `效能` > `GPU`並查看**專用GPU記憶體**（NVIDIA顯示卡也可執行`nvidia-smi`）。Ollama桌面版安裝程式會自動在連接埠`11434`執行伺服器；僅在服務停止時執行`ollama serve`。

```powershell
ollama pull gemma4:12b     # 替換為適合你VRAM的標籤
Invoke-RestMethod http://127.0.0.1:11434/v1/models
```

</TabItem>
<TabItem label="Linux">

執行`nvidia-smi`（或你的GPU廠商工具）查看VRAM。若Ollama systemd服務尚未執行，請在另一個終端機啟動`ollama serve`：

```bash
ollama pull gemma4:12b     # 替換為適合你VRAM的標籤
curl -fsS http://127.0.0.1:11434/v1/models
```

</TabItem>
<TabItem label="Mac">

開啟Apple選單 > **關於這台Mac**查看總統一記憶體（macOS會將一部分統一記憶體配置給GPU）。Ollama桌面版應用程式會自動在連接埠`11434`執行背景伺服器；僅在沒有桌面應用程式的無介面環境中才需要執行`ollama serve`。

```bash
ollama pull gemma4:12b     # 替換為適合你記憶體的標籤
curl -fsS http://127.0.0.1:11434/v1/models
```

</TabItem>
</Tabs>

記下確切安裝的標籤，因為這就是你要註冊的`代號名稱`（Model Name）：

```sh
ollama list
# NAME              ID            SIZE
# gemma4:12b        a1b2c3d4...   7.6 GB
```

## 2. 在Discord中註冊

執行`/providers`（全伺服器）或`/personal providers`（僅個人），選擇`+ 新增自訂端點`，並輸入：

| 欄位 | Ollama的值 |
|-------|------------------|
| `端點標籤`（`endpoint_label`） | 你自訂的名稱，例如`home-ollama` |
| `API 相容性` | `OpenAI 相容`（推薦）或`Ollama` |
| `端點 URL`（`endpoint_url`） | `OpenAI 相容`使用`http://127.0.0.1:11434/v1` · `Ollama`使用`http://127.0.0.1:11434` |
| `驗證權杖`（`auth_token`） | *（留空）* |

:::tip[選擇與API相容性相符的URL]
`OpenAI 相容`與`Ollama`均接受單純的根路徑並將其正規化為`/v1`基底。`/chat/completions`會自動附加，因此請勿手動新增。已帶有路徑的URL（例如`https://openrouter.ai/api/v1`或閘道前綴）會逐字儲存。
:::

儲存連線後，選取它並從其模型下拉選單中選擇`+ 新增文字模型`。填寫：

- **`代號名稱`（確切API ID）：** `gemma4:12b`，即來自`ollama list`的確切標籤。
- **`脈絡視窗`（Context Window Override）：** 選填，僅限Ollama / KoboldCPP。設定此值（例如`8192`、`16384`）可提高Ollama的預設`num_ctx`，否則預設值過小可能會截斷TomoriBot的長脈絡。留空則使用伺服器預設值。
- **開關：** 若模型支援函式呼叫請啟用`工具呼叫`；僅對視覺模型啟用`圖片輸入`；若模型能良好處理JSON結構描述請啟用`結構化輸出`。在我們的範例中，Gemma 4全部支援，因此請全部勾選。

TomoriBot會在你儲存時驗證連線。若回報端點無法連線，通常是因為`localhost`/Docker不一致或缺少/多餘的`/v1`（請參閱[注意事項與陷阱](#notes--gotchas)）。

新增模型會自動讓它成為作用中的`text`模型。開始聊天即可測試。若因某種原因未處於作用中狀態，請執行`/config` > `模型` > `切換模型`並選取你新註冊的模型。

## 3.（選用）RAG用的本機嵌入

選取已儲存的端點，並使用其模型下拉選單新增嵌入模型（例如`ollama pull nomic-embed-text`，`代號名稱`為`nomic-embed-text:latest`）。RAG功能還需要在Postgres中安裝pgvector。你可以在此查看[手動設定](/self-hosting/manual-setup/)指南。

## 4.（選用）與ComfyUI共用單一GPU
{/* anchor: 4-optional-share-one-gpu-with-comfyui */}

若文字模型與ComfyUI執行在同一個GPU上，TomoriBot可以在ComfyUI圖片或影片工作執行期間卸載文字模型。在工作期間抵達的文字回覆會等待至GPU再次可用為止。

開啟已儲存的端點，按下`編輯端點`，並在`端點行為`底下勾選`ComfyUI 工作期間卸載模型`。TomoriBot會在你儲存時檢查該URL上的伺服器類型：

- **Ollama：** 安裝即可直接運作。TomoriBot會在工作執行前要求Ollama卸載模型，Ollama則會在下一個文字請求時重新載入。
- **KoboldCpp：** 啟動KoboldCpp時加上`--admin`與`--admindir`，並將端點的驗證權杖設定為管理員密碼。TomoriBot會使用KoboldCpp的管理員重新載入API卸載模型，並在之後重新載入。

儲存時會拒絕任何其他伺服器，因為通用的OpenAI相容伺服器沒有通用的模型卸載方式。

## 其他伺服器
{/* anchor: other-servers */}

TomoriBot支援任何OpenAI相容的端點，但推薦使用以下伺服器。所有這些伺服器都使用相同的流程：只有URL與少數注意事項不同。

### KoboldCPP

- 啟動時啟用OpenAI相容性（內建）。預設：`http://127.0.0.1:5001/v1`。
- `API 相容性`：`OpenAI 相容`。`端點 URL`：`http://127.0.0.1:5001/v1`。
- 與Ollama一樣遵循`脈絡視窗`（Context Window Override）。
- 若要在ComfyUI工作期間卸載模型，啟動時請一併加上`--admin`與`--admindir`（請參閱[與ComfyUI共用單一GPU](#4-optional-share-one-gpu-with-comfyui)）。
- 載入GGUF模型；`代號名稱`是已載入模型所回報的名稱（通常是檔名主幹），請檢查KoboldCPP的`/v1/models`回應。

### llama.cpp（`llama-server`）

- 建置或安裝[llama.cpp](https://github.com/ggml-org/llama.cpp)，接著使用其隨附的OpenAI相容伺服器提供GGUF：
  ```sh
  llama-server -m model.gguf -c 16384 --host 0.0.0.0 --port 8080
  ```
- `API 相容性`：`OpenAI 相容`。`端點 URL`：`http://127.0.0.1:8080/v1`。
- 在啟動時使用`-c`設定脈絡視窗；互動視窗中的`脈絡視窗`（Context Window Override）僅限Ollama/KoboldCPP，在此處無效。
- `代號名稱`是`/v1/models`回報的名稱；可以使用`--alias my-model`給予簡潔的名稱。
- 若使用`--api-key`啟動，請將該金鑰填入`驗證權杖`。

### LM Studio

- 在LM Studio中，啟動`Local Server`（`Developer`分頁）。預設：`http://127.0.0.1:1234/v1`。
- `API 相容性`：`OpenAI 相容`。`端點 URL`：`http://127.0.0.1:1234/v1`。
- `代號名稱`是LM Studio為已載入模型顯示的識別碼。

### vLLM

- 使用OpenAI相容伺服器提供服務：`vllm serve "<model>"`可取得`http://127.0.0.1:8000/v1`。
- `API 相容性`：`OpenAI 相容`。`端點 URL`：`http://127.0.0.1:8000/v1`。
- 若使用`--api-key`啟動vLLM，請將該金鑰填入`驗證權杖`。
- `代號名稱`是提供的模型路徑/名稱（與`/v1/models`相符）。

### LiteLLM（多後端代理）

- 執行LiteLLM代理；預設：`http://127.0.0.1:4000/v1`。
- `API 相容性`：`OpenAI 相容`。`端點 URL`：`http://127.0.0.1:4000/v1`。
- `代號名稱`是你在LiteLLM設定中定義的模型別名。
- 若代理強制要求主金鑰，請在`驗證權杖`中設定。

### ChatMock（ChatGPT帳號 / Codex CLI）

因為需要系統提示詞變通方案，擁有專門的指南：
[設定：ChatMock](/self-hosting/local-endpoints/proxies-and-remote-access/setup-chatmock/)。

## 從Hugging Face選擇模型

除了Ollama精選的模型庫之外，[Hugging Face](https://huggingface.co)還託管了成千上萬個社群模型。KoboldCPP、llama.cpp與LM Studio都可以載入GGUF格式，這是一種下載後將伺服器指向該檔案的單一檔案套件。

1. **尋找GGUF：** 在Hugging Face上搜尋你的模型加上「GGUF」；像[bartowski](https://huggingface.co/bartowski)這樣的社群量化者通常在多數熱門模型發布後不久就會推出GGUF版本。偏好使用instruct/chat變體（名稱結尾為`-Instruct`或`-Chat`）；基礎模型無法進行對話。
2. **挑選適合你VRAM的量化版本：** 存放庫會列出同一個模型的多種量化等級，檔案大小約略等於所需的VRAM（再加上約1到2GB用於脈絡，規則與上方的[大小規格表](#which-size-should-i-pull)相同）。下載符合你選擇的單一`.gguf`檔案。
3. **載入模型：** 使用該檔案啟動KoboldCPP或`llama-server`（請參閱[其他伺服器](#other-servers)），然後如常在Discord中註冊端點。

:::tip[該選哪種量化？Q4或Q5是最佳平衡點]
量化透過以較少位元儲存每個權重來縮小模型，代價是微小的品質損失。像`Q4_K_M` / `Q5_K_M`這樣的代號表示每個權重的位元數：**4-bit（Q4）或5-bit（Q5）通常是最佳平衡點**，能以約8-bit一半的體積保留大部分品質。低於4-bit品質會迅速下降。而且在固定的VRAM預算下，**Q4的較大模型通常優於Q8的較小模型**。
:::

## 注意事項與陷阱
{/* anchor: notes--gotchas */}

- **Bot分開架設？** 請依照[透過Cloudflare安全遠端存取](/self-hosting/local-endpoints/proxies-and-remote-access/cloudflare-tunnel/)設定。生產環境的bot無法透過`127.0.0.1`連上你的電腦；該指南會為引擎提供公開HTTPS網址。在支援的情況下請使用引擎的API金鑰；Access與Caddy屬於選用的額外強化措施。
- **每個標籤一個端點項目：** 若要註冊共用同一個伺服器的多個模型，請選取已儲存的端點並再次使用其模型下拉選單。真正不同的伺服器或API協定才使用相異的標籤。
- **`代號名稱`即為API識別碼：** 它是發送到伺服器的確切字串。填寫錯誤是「已連線但回覆失敗」最常見的原因。
- **在Docker中執行TomoriBot？** 容器內的`localhost`並非你的主機。請使用`http://host.docker.internal:<port>`或主機的區域網路IP，並將模型伺服器繫結到`0.0.0.0`。隨附的Compose檔案在Linux上也會對應這個名稱。若在Linux上使用自己的Compose檔案或`docker run`，請加上`extra_hosts: ["host.docker.internal:host-gateway"]`（`docker run`請加上`--add-host=host.docker.internal:host-gateway`）。
- **私人位址需要透過`ALLOW_PRIVATE_NETWORK`允許：** 設為`true`時，`localhost`、區域網路主機與`host.docker.internal`上的端點可透過純HTTP運作。`host:port`清單（例如`localhost:5001`）只允許這些伺服器，適合與整個Discord伺服器共用你的模型。`FETCH_URL_ALLOW_PRIVATE_NETWORK`是用於`fetch_url`工具的獨立設定，不會改變端點規則。
