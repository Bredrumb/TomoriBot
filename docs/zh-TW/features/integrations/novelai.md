NovelAI 連接文字模型（`GLM 4.6`、`Xialong`、`Kayra`、`Erato`）與動漫影像生成。你可以將 NovelAI 同時用於兩者，或將其影像生成與其他聊天供應商搭配使用。

## 文字模型與訂閱
<!-- anchor: text-models-and-subscription -->

`GLM 4.6` 是預設的文字模型。`Xialong` 與 `Erato` 需要有效的 Opus 訂閱。選取 `Xialong` 時會檢查你已儲存的伺服器金鑰或個人金鑰；若你在新增金鑰之前選取它，該檢查會在新增金鑰時執行。提供服務的金鑰訂閱決定了脈絡額度。伺服器管理員可使用 `/novelai usage` 查看 Opus 生成額度。

NovelAI 的 [Chat Format 指南](https://docs.novelai.net/en/text/chatformat/) 介紹了用於 `Kayra` 與 `Erato` 的故事流風格方法；`GLM 4.6` 與 `Xialong` 使用獨立的聊天範本。下方的過濾與潤色規則是 TomoriBot 的適配實現。

## 取樣預設集
<!-- anchor: sampling-presets -->

切換文字模型時，會為選取的模型載入 `Carefree-Kayra`、`Erato-Shosetsu` 或 `Default-Xialong`；`GLM 4.6` 則使用其自身的預設值。切換時會重設 temperature、top-k、top-p 與 min-p，並為伺服器與個人模型切換啟用這些取樣器。可在 `/config` > `模型` > `文字取樣器與參數` 中變更預設集或取樣器；後續的編輯會保持生效，且在相同模型上更換金鑰會保留這些設定。

## 脈絡與設定
<!-- anchor: context-and-settings -->

被省略的設定會保留在 `/config` > `行為` > `一般行為` 中以供其他供應商使用。

| 內容或設定 | NovelAI 處理方式 |
|---|---|
| 人格屬性、範例對話、會話與記憶 | 保留，包括可見的個人記憶與短期記憶。隱私與記憶標籤過濾器仍會套用。 |
| 系統、人格與頻道提示詞；脈絡備忘；擬人化規則；行為偏好；SillyTavern 指令 | 省略。Xialong 使用 NovelAI 的系統提示詞；GLM、Kayra 與 Erato 沒有系統區塊。 |
| 狀態、時間/頻道/伺服器資訊、文件以及表情符號/貼圖/立繪清單 | 省略。 |
| 記憶工具提示 | 省略，包括在個人覆寫或後備前建立的提示。 |
| ATTG 中繼資料與品質星級 | ATTG 代表作者（Author）、標題（Title）、標籤（Tags）與類型（Genre）。Xialong 將中繼資料放在其持久資訊的最前方，並預設為 4 顆星。Erato 使用設定的星級；Kayra 省略星級。 |
| 回覆預填 | 在預填控制項允許時保留。 |
| 工具與媒體 | 無文字模型工具呼叫或圖片/影片輸入。斜線指令與獨立的影像生成指令仍可使用。 |
| Token 限制 | 在本機計算，並為回覆預留空間。設定的回覆長度優先於預設集長度，且可能會縮減以容納內容。 |

即使已關閉共用的發言者停止設定，已知的外部發言者標籤與單獨成行的 `---` 或 `***` 仍會停止輸出。回覆人格的名稱、別名與立繪標籤仍然允許出現。本機防護會保留程式碼；字面 API 停止標記仍可在產生的程式碼內部比對到。

## 脈絡裁剪
<!-- anchor: context-trimming -->

記憶最多使用脈絡視窗的 20%，較舊的項目會優先移除。若提示詞仍無法容納，TomoriBot 會依照以下順序裁剪：

| 順序 | 移除的內容 | 保護的內容 |
|---|---|---|
| 1 | 多餘的範例對話 | 一組可用的範例對話 |
| 2 | 記憶，較舊的項目優先 | 無最低限制 |
| 3 | 較早的對話歷史記錄 | 最多兩組近期的歷史對話 |

人格屬性、ATTG 中繼資料與當前回合也會受到保護。若受保護的脈絡無法容納，生成將會失敗。裁剪不會改變已儲存的記憶與訊息。

`/tool prompt snapshot` 會顯示最終提示詞、token 數量、回覆上限與裁剪報告。

## 文字潤色與 Discord 傳送
<!-- anchor: text-polishing-and-discord-delivery -->

潤色僅會在計算 token 之前，修改傳送給全部四個 NovelAI 模型的歷史記錄、記憶與範例對話副本。已儲存的文字與其他供應商不受影響；文法不會被重寫。

- **文字首字母規範大寫**：拉丁文字句與行首大寫；已知的人格名稱使用其設定的大小寫。
- **正文行加入標點符號**：補上結尾缺失的句號，同時保留現有的標點符號、換行與空行。
- **格式化正文潤色**：`*kisses juno*` 變成 `*Kisses Juno.*`。粗體、底線、刪除線與防雷標記遵循相同規則；行內強調保留其大小寫，名稱除外。
- **程式碼與標記保持原樣**：程式碼、URL、提及、Discord 標記、清單、標題、區塊引用、表格與分隔線保留其內容或結構。
- **尊重非正文開頭與結尾**：以程式碼區塊、URL、提及、表情符號或非拉丁字母開頭的行會略過句子格式化。表情符號、顏文字、程式碼與連結結尾不會加上額外的句號。
- **長期記憶使用純文字內容**：加入的擁有者標籤、資料庫 ID 與標籤前置詞會被省略；解析後的名稱會保留。
- **產生的歷史記錄註解會被移除**：回覆參照、反應中繼資料與管理通知會被省略。手勢變成動作；場景與摘要失去其系統包裝。包含 `System:` 的字面使用者文字會被保留。
- **預填文字維持完全一致**：明確的回覆預填與接續片段保持不變。
- **Discord 傳送遵循你的設定**：擬人化功能仍會控制大小寫、標點符號與訊息拆分。後續的歷史記錄會再次被潤色；遺失的標點符號無法精準還原。

## 影像生成
<!-- anchor: image-generation -->

在 `/config` > `模型` > `切換模型` 下將模型指派給 `NovelAI 圖片` 欄位。成員可以直接使用 `/novelai generate image` 產生圖片，或者在目前的文字供應商支援工具呼叫時在聊天中提出請求。

`Default + Image Generation Expert` 預設集對 NovelAI 使用圖庫風格的標籤，並在需要互動或文字配置時加上簡短描述。對於有多個角色的場景，TomoriBot 會將共用背景與鏡頭指示與每個角色的外觀及動作分開處理。

若需要清晰可讀的對白，請讓 TomoriBot 加入確切的對話。NovelAI 圖片工具會自動將角色對白放入結尾的 `Text:` 區塊。V4 與 V4.5 支援英文文字；V5 也支援日文與中文。招牌或螢幕上的文字可在共用場景提示詞中描述。請保持要求的文字簡短，並避免在正向標籤中加入 `no text`。位置與排版（包括垂直日文排版）屬於建議而非保證。
